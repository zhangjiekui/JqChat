以下是详细分析和排查建议：

### 1. 为什么说不正常？

*   **当前速度 (`LnkSta`)**: `Speed 2.5GT/s` 对应的是 **PCIe 1.0** 标准。
*   **支持能力 (`Capabilities`)**: 输出末尾显示 `Physical Layer 16.0 GT/s`，这说明你的显卡硬件本身支持 **PCIe 4.0**。
*   **关键词 `downgraded`**: 这明确表示系统尝试以更高的速度（如 3.0 或 4.0）进行握手，但失败了，最终被迫降级到最低的 1.0 速度以维持连接。
*   **性能影响**: PCIe 1.0 x16 的带宽非常低（约 4GB/s 单向），而现代显卡通常需要 PCIe 3.0 x16 (约 16GB/s) 或 PCIe 4.0 x16 (约 32GB/s)。这会导致显卡性能大幅损失，尤其是在需要频繁交换数据的应用中（如深度学习、高分辨率游戏、渲染）。

### 2. 可能的原因及解决方法

请按照以下顺序进行排查：

#### A. 物理接触问题（最常见）
*   **原因**: 显卡金手指氧化、插槽内有灰尘，或者显卡没有完全插到底。
*   **解决**:
    1.  关机断电。
    2.  拔下显卡，用橡皮擦轻轻擦拭金手指。
    3.  清理主板 PCIe 插槽（可用压缩空气）。
    4.  重新用力将显卡插紧，确保卡扣扣好。

#### B. BIOS/UEFI 设置
*   **原因**: 主板 BIOS 中 PCIe 速度被手动锁定在了 Gen 1，或者 "Auto" 模式识别错误。
*   **解决**:
    1.  进入 BIOS 设置。
    2.  找到 PCIe 配置选项（通常在 `Advanced` -> `PCIe Configuration` 或 `Chipset` 下）。
    3.  将 PCIe Speed 从 `Auto` 或 `Gen1` 改为 `Gen3` 或 `Gen4`（根据你的显卡和主板支持情况）。
    4.  保存重启。

#### C. 使用了 PCIe 延长线（Riser Cable）
*   **原因**: 如果你使用了显卡延长线（常见于 ITX 机箱或矿机），很多廉价的延长线只支持 PCIe 3.0 甚至 1.0/2.0，或者线材质量差导致信号完整性不足，被迫降速。
*   **解决**:
    1.  尝试直接将显卡插在主板上，不使用延长线。
    2.  如果必须使用，请购买支持 PCIe 4.0 的高质量延长线，并在 BIOS 中强制指定对应的 Gen 速度（有时 Auto 会失败，需手动指定 Gen3）。

#### D. 插槽带宽共享
*   **原因**: 某些主板上，特定的 PCIe 插槽会与 M.2 接口或其他 PCIe 插槽共享通道。如果插了多个设备，带宽会被拆分或降速。
*   **解决**: 查阅主板说明书，确认你使用的插槽是否是全速 x16 插槽（通常是靠近 CPU 的第一条插槽）。尝试更换到第一条 PCIe x16 插槽。

#### E. 电源供电不足
*   **原因**: 虽然较少见，但如果电源供电不稳定，可能导致 PCIe 链路训练失败。
*   **解决**: 确保显卡外接供电线已插好，且电源功率足够。

#### F. 系统电源管理 (ASPM)
*   **原因**: Linux 内核的主动状态电源管理 (ASPM) 有时会导致链路不稳定。
*   **解决**: 尝试在 GRUB 启动参数中添加 `pcie_aspm=off`，然后更新 grub 并重启，观察 `lspci` 输出是否恢复正常。

### 3. 如何验证修复？

修复后，再次运行相同的命令：
```bash
sudo lspci -vvv -s $(lspci | grep -i nvidia | head -1 | awk '{print $1}') | grep -E 'LnkSta:|Capabilities'
```

**正常的输出应该类似于：**
*   **PCIe 3.0 显卡**: `LnkSta: Speed 8GT/s, Width x16`
*   **PCIe 4.0 显卡**: `LnkSta: Speed 16GT/s, Width x16`
*   **且不应该出现 `(downgraded)` 字样。**

**总结：** 目前的状态是**异常**的，建议优先检查**显卡是否插紧**以及**BIOS 中的 PCIe 速度设置**。

在 Linux 系统下，有多种方法可以查看机器的 PCIe 类型（版本/代数）和链路状态。以下是常用命令和解读方法：

---

### 🔹 方法一：使用 `lspci` 查看具体设备的 PCIe 速度（推荐）

```bash
# 查看 NVIDIA 显卡的 PCIe 链路状态
sudo lspci -vvv -s $(lspci | grep -i nvidia | head -1 | awk '{print $1}') | grep -E 'LnkCap:|LnkSta:'

# 或查看任意 PCIe 设备（如网卡、NVMe）
sudo lspci -vvv | grep -A 2 -E 'PCI express|LnkCap:|LnkSta:'
```

**关键字段解读：**
| 字段 | 含义 | 速度对应关系 |
|------|------|-------------|
| `LnkCap:` | 设备**支持**的最大能力 | `2.5GT/s`=PCIe 1.0, `5GT/s`=2.0, `8GT/s`=3.0, `16GT/s`=4.0, `32GT/s`=5.0 |
| `LnkSta:` | 当前**实际运行**的链路状态 | 同上，若出现 `(downgraded)` 表示降速 |

✅ 正常示例（PCIe 4.0 x16 全速）：
```
LnkCap: Port #0, Speed 16GT/s, Width x16
LnkSta: Speed 16GT/s, Width x16
```

❌ 异常示例（降速到 PCIe 1.0）：
```
LnkCap: Port #0, Speed 16GT/s, Width x16
LnkSta: Speed 2.5GT/s (downgraded), Width x16
```

---

### 🔹 方法二：使用 `lspci -t` 查看 PCIe 拓扑树

```bash
lspci -t
```

输出示例：
```
-+-[0000:00]---00.0-[01]--+-00.0  NVIDIA Corporation ...
                          +-00.1  Audio device
```
可辅助判断设备挂载在哪个 PCIe 根端口下，结合 `-vvv` 进一步分析。

---

### 🔹 方法三：使用 `dmidecode` 查看主板 PCIe 插槽规格

```bash
sudo dmidecode -t slot
```

可查看主板物理插槽的设计规格（如 "PCI Express x16 Gen4"），但**不代表当前设备实际协商的速度**，需与 `lspci` 结果结合判断。

---

### 🔹 方法四：使用 `lshw` 获取简洁硬件摘要

```bash
sudo lshw -class display -businfo  # 显卡
sudo lshw -class network -businfo  # 网卡
```

部分系统会显示 `configuration: lane=16 speed=16GT/s` 等信息。

---

### 🔹 方法五：使用 `pciutils` 的 `setpci`（高级用户）

```bash
# 查看设备 PCIe 链路状态寄存器（需知道 BDF，如 01:00.0）
sudo setpci -s 01:00.0 CAP_EXP+12.w  # LnKSta 寄存器原始值
```
⚠️ 此方法需手动解析十六进制值，一般调试用，日常推荐用 `lspci -vvv`。

---

### 🔹 附：PCIe 速度与代数对照表

| GT/s | PCIe 代数 | 单向带宽（x16） | 双向带宽（x16） |
|------|-----------|----------------|----------------|
| 2.5  | Gen 1     | ~4 GB/s        | ~8 GB/s        |
| 5.0  | Gen 2     | ~8 GB/s        | ~16 GB/s       |
| 8.0  | Gen 3     | ~16 GB/s       | ~32 GB/s       |
| 16.0 | Gen 4     | ~32 GB/s       | ~64 GB/s       |
| 32.0 | Gen 5     | ~64 GB/s       | ~128 GB/s      |

> 💡 注意：实际可用带宽约为理论值的 97%~98%（因 128b/130b 或 8b/10b 编码开销）。

---

### 🔍 快速诊断脚本（一键检查显卡 PCIe 状态）

```bash
#!/bin/bash
DEV=$(lspci | grep -i nvidia | head -1 | awk '{print $1}')
if [ -z "$DEV" ]; then
  echo "❌ 未找到 NVIDIA 设备"
  exit 1
fi
echo "🔍 检查设备 $DEV 的 PCIe 链路状态："
sudo lspci -vvv -s $DEV | grep -E 'LnkCap:|LnkSta:'
```

保存为 `check_pcie.sh`，赋予执行权限后运行即可。

---

✅ **总结建议**：
1. 优先用 `lspci -vvv | grep Lnk` 查看 **实际协商速度（LnkSta）**；
2. 若发现 `(downgraded)` 或速度远低于 `LnkCap`，按之前建议排查：重插显卡、检查 BIOS 设置、更换 PCIe 延长线、关闭 ASPM 等；
3. 主板插槽规格（`dmidecode`）≠ 实际运行速度，务必以 `LnkSta` 为准。

```
-+-[0000:00]-    ← PCIe 根复合体 #1 (CPU 1 / PCH)
+-[0000:15]-     ← PCIe 根复合体 #2
+-[0000:26]-     ← PCIe 根复合体 #3
...（共 30+ 个根总线域）
```

✅ **关键结论**：
1. **这是服务器/工作站平台**（如 Intel C62x/C741 芯片组、或 AMD EPYC），不是普通消费级主板
2. **多 PCIe Root Complex**：每个 `[0000:xx]` 代表一个独立的 PCIe 根端口域，通常对应：
   - CPU 直连的 PCIe 通道
   - PCH（芯片组）扩展的 PCIe 通道
   - PCIe Switch 扩展的下级总线
3. **存在 PCIe 交换结构**：如 `0e.0-[01-02]----00.0-[02]` 表示经过 PCIe Switch 级联

### 🔧 如何查看具体设备的 PCIe 类型/速度？

`lspci -t` 只能看拓扑，**看不到速度**。请配合以下命令：

#### 1️⃣ 先定位你的目标设备（如 NVIDIA 显卡、NVMe 硬盘）
```bash
# 列出所有 NVIDIA 设备
lspci | grep -i nvidia

# 列出所有 NVMe 设备
lspci | grep -i nvme

# 列出所有 VGA/3D 设备
lspci | grep -E 'VGA|3D'
```

假设输出：
```
02:00.0 VGA compatible controller: NVIDIA Corporation Device xxxx
```

#### 2️⃣ 查看该设备的 PCIe 链路详情
```bash
# 替换 02:00.0 为你的设备 BDF
sudo lspci -vvv -s 02:00.0 | grep -E 'LnkCap:|LnkSta:'
```

✅ 正常输出示例：
```
LnkCap: Port #0, Speed 16GT/s, Width x16, ASPM not supported
LnkSta: Speed 16GT/s, Width x16, TrErr- Train- SlotClk+ DLActive- BWMgmt- ABWMgmt-
```
→ 表示运行在 **PCIe 4.0 x16 全速**

❌ 异常输出示例：
```
LnkSta: Speed 2.5GT/s (downgraded), Width x16
```
→ 表示降速到 **PCIe 1.0**，需排查（见下文）

### 🗂️ 你的拓扑中典型路径解读

| 拓扑片段 | 含义 |
|---------|------|
| `-[01-02]----00.0-[02]` | PCIe Switch，总线 01~02 是下游，设备在总线 02 上 |
| `-[81]----00.0` | 直连设备（如 NVMe/网卡），挂载在总线 81 |
| `-[a8]--` / `-[a9]--` | 空插槽或未插设备的 PCIe 槽位 |

💡 **小技巧**：用 `lspci -t -v` 可显示设备名称（部分系统支持），更易定位：
```bash
lspci -t -v | grep -A 3 -i nvidia
```

---

### ⚠️ 服务器平台特别注意

1. **CPU 直连 vs PCH 通道**：
   - CPU 直连插槽：延迟低、带宽高（优先插显卡/高速网卡）
   - PCH 扩展插槽：经过 DMI 总线，带宽受限（适合接 SATA/USB 设备）
   - 查主板手册确认哪个插槽是 "CPU1 PCIe x16 Gen4"

2. **PCIe bifurcation（通道拆分）**：
   - 服务器常支持 x16 拆分为 4x4 或 2x8
   - 若拆分配置错误，可能导致设备识别异常或降速
   - 需在 BIOS 中设置 `PCIe Slot Configuration → Bifurcation Mode`

3. **ACS / IOMMU 影响**：
   - 虚拟化场景下，ACS（Access Control Services）可能限制 P2P 通信
   - 如需 GPU Direct / NVLink，可能需要内核参数 `pcie_acs_override=downstream`

### 🛠️ 快速诊断脚本（自动检查所有设备链路状态）

```bash
#!/bin/bash
echo "🔍 扫描所有设备的 PCIe 链路状态..."
for dev in $(lspci | awk '{print $1}'); do
  info=$(sudo lspci -vvv -s $dev 2>/dev/null | grep -E 'LnkSta:' | head -1)
  if [[ -n "$info" && "$info" != *"LnkSta:"* ]]; then
    continue
  fi
  if [[ -n "$info" ]]; then
    name=$(lspci -s $dev | cut -d' ' -f2-)
    echo -e "\n[$dev] $name"
    echo "  $info"
    # 标记降速设备
    if echo "$info" | grep -q "downgraded"; then
      echo "  ⚠️  WARNING: Link downgraded!"
    fi
  fi
done
```

### ✅ 下一步建议

1. **先确认你要查哪个设备**（显卡？NVMe？网卡？）
2. **用 `lspci | grep -i xxx` 找到它的 BDF**（如 `02:00.0`）
3. **用 `sudo lspci -vvv -s 02:00.0 | grep Lnk` 看实际速度**
4. 如果看到 `(downgraded)` 或速度不符预期 → 按之前建议排查：
   - 重插设备 / 清理金手指
   - BIOS 中设置 PCIe Speed = Gen4/Gen3（非 Auto）
   - 检查是否用了劣质 PCIe 延长线
   - 尝试关闭 ASPM：内核参数加 `pcie_aspm=off`

### 🔍 核心问题分析

1.  **硬件平台确认**：
    *   **服务器型号**：H3C UniServer R5300 G6（企业级服务器）。
    *   **CPU**：Intel Xeon Platinum 8558P（支持 PCIe 5.0）。
    *   **显卡**：8x NVIDIA GeForce RTX 4090（消费级显卡，支持 PCIe 4.0）。
    *   **插槽规格**：`dmidecode` 显示插槽支持 **PCIe 5.0 x16**。

2.  **故障现象**：
    *   **期望速度**：16GT/s (PCIe 4.0) 或 32GT/s (PCIe 5.0)。
    *   **实际速度**：**2.5GT/s (PCIe 1.0)**，且所有 8 张卡均显示 `(downgraded)`。
    *   **日志特征**：`dmesg` 中未见严重的 PCIe AER 报错，说明链路在 1.0 速度下是稳定的，只是无法协商到高速。

3.  **根本原因推测**：
    *   **BIOS  PCIe 速度协商失败**：服务器 BIOS 默认通常为 `Auto`。消费级显卡（RTX 4090）与企业级服务器主板（H3C）在 PCIe 信号时序上可能存在兼容性差异，导致自动协商失败，被迫降级到最保守的 PCIe 1.0 以保证稳定性。
    *   **PCIe Riser 卡（转接卡）问题**：2U/4U 服务器安装 8 张显卡通常需要通过 PCIe Riser 卡扩展。如果 Riser 卡接触不良、型号不匹配或信号质量差，会导致降速。
    *   **供电信号干扰**：8 张 4090 功耗极高，启动瞬间的电流波动可能影响 PCIe 链路训练信号。

### 🛠️ 解决方案（按优先级排序）

请依次尝试以下步骤，每步操作后重启并运行 `lspci` 检查 `LnkSta` 速度。

#### 1️⃣ 修改 BIOS 设置（最可能的解决方案）
服务器 BIOS 通常不会为消费级显卡优化自动协商策略，需要**手动强制指定速度**。

*   **操作步骤**：
    1.  重启服务器，按 `Del` 或 `F11` 进入 BIOS 设置。
    2.  找到 **Advanced** -> **PCIe Configuration** 或 **Chipset Configuration**。
    3.  找到 **PCIe Speed** 或 **Max PCIe Link Speed** 选项。
    4.  将设置从 `Auto` 改为 **`Gen4`** (因为 RTX 4090 最高支持 Gen4)。
        *   *注意：不要选 Gen5，显卡不支持；不要选 Auto，目前证明 Auto 失败。*
    5.  确保 **Above 4G Decoding** 和 **Re-Size BAR Support** 已设置为 **`Enabled`**。
    6.  保存并重启。

#### 2️⃣ 检查物理连接与 Riser 卡
H3C R5300 这类服务器通常使用 PCIe 转接板（Riser）来安装多卡。

*   **操作步骤**：
    1.  **断电**并打开机箱。
    2.  拔出所有显卡和 **PCIe Riser 卡**。
    3.  检查 Riser 卡金手指和主板插槽是否有灰尘/氧化，用橡皮擦擦拭。
    4.  **重新插紧** Riser 卡，确保螺丝固定牢固（松动会导致信号完整性下降）。
    5.  重新插回显卡，确保显卡垂直插入，无歪斜。
    6.  检查显卡供电线（12VHPWR）是否插到底（听到咔哒声），供电不足也会导致链路训练异常。

#### 3️⃣ 更新 BIOS 和 BMC 固件
H3C 服务器对新硬件（如 RTX 40 系列）的支持可能需要较新的 BIOS 版本。

*   **操作步骤**：
    1.  访问 H3C 官网支持页面，查询 **UniServer R5300 G6** 的最新 BIOS 和 BMC 固件。
    2.  如果有更新，优先升级 BIOS。厂商常在更新中修复 PCIe 兼容性列表。

#### 4️⃣ 内核参数调整（软件层补救）
虽然 `lspci` 显示 ASPM 已禁用，但可以通过内核参数强制关闭 PCIe 电源管理，排除干扰。

*   **操作步骤**：
    1.  编辑 GRUB 配置：
        ```bash
        sudo nano /etc/default/grub
        ```
    2.  在 `GRUB_CMDLINE_LINUX_DEFAULT` 行中添加：
        ```text
        pcie_aspm=off pci=realloc=off
        ```
    3.  更新 GRUB 并重启：
        ```bash
        sudo update-grub  # Ubuntu/Debian
        # 或
        sudo grub2-mkconfig -o /boot/grub2/grub.cfg  # CentOS/RHEL
        reboot
        ```

#### 5️⃣ 单卡隔离测试（排查硬件故障）
如果以上均无效，需排查是否是主板或 Riser 卡硬件故障。

*   **操作步骤**：
    1.  只保留 **1 张显卡** 插在 **CPU 直连的主插槽**（通常是 Slot 9 或 Slot 5，参考主板手册）。
    2.  拔掉其他 7 张卡。
    3.  重启检查速度。
    4.  如果单卡正常，说明是 **多卡并发时的信号干扰** 或 **电源功率不足**。
    5.  如果单卡依然 2.5GT/s，说明该插槽或 Riser 卡存在硬件兼容性问题。
